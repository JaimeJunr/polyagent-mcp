Refresh de modelos e engines do polyagent

Workspace .ralph/polyagent/model-refresh-2026 · tier starter · framework CRIA

⏱ Time-box: este PRD deve fechar em 1 sessão. Escopo > tempo = subir de tier (quick→starter→full).

C — Contexto

O polyagent-mcp roteia trabalho para CLIs de coding agent headless. A matriz TIERS (src/cli.ts) congela um mapa nível→modelo escrito quando GPT-5.6 Sol e Grok 4.5 eram o topo. Os rankings públicos de setembro/2026 (Artificial Analysis Coding Agent Index, Code Arena WebDev) mostram outra fronteira: Claude Fable 5.1 (max) e GPT-6 Astra (max) lideram, o Sol caiu para o meio da tabela e o Grok 4.5 é geração anterior. Como o nível é a única alavanca que o chamador tem, um mapa desatualizado degrada silenciosamente toda delegação.

Em paralelo, o host já tem instaladas CLIs headless que o bridge não sabe dirigir — agy (Google), opencode (multi-provider), kimi (Moonshot) e muse (Meta). O spike cli-dialects.md confirmou que as quatro são spawnáveis e mapeou o dialeto completo de agy, opencode e kimi; o de muse ficou parcial.

Achado que define o critério: os rankings medem $/task de API pay-per-token, mas codex, grok, claude, agy e kimi rodam em assinatura (custo marginal ≈ 0). Só opencode (Google, Groq, OpenRouter) e muse cobram por token. Portanto cada nível deve escolher o modelo mais capaz que a assinatura já paga; engine de API key só se justifica para alcançar o que assinatura nenhuma alcança. A economia que o bridge existe para dar é de contexto, não de token.

I — Impacto esperado

  • Cada nível de delegate/fan_out aponta para o melhor modelo disponível na assinatura correspondente, sem aumentar custo marginal.
  • O bridge deixa de estar preso a 3 assinaturas: engine nova vira acréscimo de dialeto, não reescrita — o padrão buildArgs/parseOutput/ENGINE_CAPABILITIES absorve as quatro candidatas.
  • Falha de cota em uma assinatura passa a ter mais alternativas reais de fallback.
